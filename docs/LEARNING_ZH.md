# 从能运行到能解释

## 今天先做什么

在项目目录执行：

```bash
.demo-venv/bin/python -m construction_slam.demo --gif
```

打开 `artifacts/demo.gif`。灰色是测量累积的地图；绿色是真值轨迹；橙色是带偏差的里程计；蓝色是扫描匹配修正后的轨迹；红点表示相对基线连续出现的新增表面。第120帧开始出现新结构。右图是定位误差，不是算法置信度。

## 五次学习任务

1. **坐标系**：读 `core.py` 的 transform / compose / relative。手算机器人转90度后，前方一点在地图里是什么坐标，再运行坐标变换测试。
2. **激光与噪声**：读 `simulation.py`。理解射线与线段求交、遮挡以及量程。把噪声从0.012改到0.05米，保存到新的输出目录并比较。
3. **ICP**：读 icp。依次解释最近邻、距离门限、裁剪、SVD、旋转反射修正、收敛。关闭裁剪再实验，不要预设一定变差。
4. **地图变化**：读 ChangeDetector。尝试把连续帧数从3改为1和5。解释延迟与噪声误检的权衡，以及“没见过”和“新出现”为什么不等价。
5. **实验报告**：用至少5个seed，报告均值和最差值；加入走廊、遮挡、大位移失败场景。之后再做ROS2/Gazebo联调。

## 两分钟演示

“我做的是面向变化场景的二维激光建图教学原型。机器人先扫描基线场景，再观察新增结构。我用带偏差里程计预测位姿，用裁剪ICP做扫描到地图匹配，然后累积点云，并把连续观测到的新增表面标出来。这里展示同一初始坐标系下的定位误差。实验很简化，没有回环后端、语义识别或实机验证。”

理解并亲自复现实验后，再用自己的语言讲这段；说明使用了AI辅助搭建，以及你亲自验证、修改了什么。

## 面试容易问到的点

- ICP为什么需要初值？最近邻可能错误，优化只寻找局部解。
- 为什么不是完整SLAM？这里只做前端和增量地图，没有回环检测和全局一致性优化。
- 为什么地图不是直接用仿真真值？估计器只接收扫描与带噪运动；真值仅用于传感器生成和评分。
- 红点就是施工构件吗？不是，只是相对基线的新几何表面，可能误检。
- 新构件是否被屏蔽出定位？没有；距离门限与裁剪能减轻部分外点影响，不能保证排除所有变化。
- 真实机器人会遇到什么？外参、时钟、运动畸变、轮滑、玻璃反射、动态人群和几何退化。
- 接下来最有价值的工作？可复现的Gazebo实验、成熟算法对照、变化检测定量评估。

## 新增学习阶段：构件偏差检测

阅读 [设计检查说明](INSPECTION_ZH.md)，再读 `inspection.py`。重点解释有符号矩形距离、鲁棒损失、单平面为什么无法确定沿平面方向的位置，以及JSON建议动作与真正规划闭环的区别。旧演示讲稿现在可补充：“在设计预先对齐、构件尺寸已知的条件下，我还评估了二维构件位置和角度偏差。”
